## 1. 背景

越南等地的中资工厂由中方管理者编写中文作业指导书（SOP），一线工人的母语是越南语。现在的做法是人工翻译、打印张贴，带来三个问题：

- SOP 改版频繁时，翻译和替换工位上的文件跟不上，工位上容易留着旧版本；
- 不同译者对同一个术语译法不一，工人理解有偏差；
- 工人遇到问题只能找懂中文的主管或翻译，响应慢。

## 2. 目标与非目标

**目标**

- G1：SOP 从上传、翻译、审核到发布形成受控流程，工人看到的始终是最新的已发布版本
- G2：翻译遵循工厂术语表，术语译法统一
- G3：工人能用越南语自助查询 SOP 内容，回答可以追溯出处
- G4：AI 能力的质量和成本可以度量

**非目标（本期不做）**

- 原生 App（工人端使用移动网页）
- 语音输入与朗读
- 工人签收与培训记录（涉及工人个人数据，放到二期）
- 设备、工单、MES 等生产管理功能
- 计费与付费
- 越南语以外的目标语言（但架构上必须支持扩展）

## 3. 用户角色

| 角色 | 说明 | 是否需要账号 |
|---|---|---|
| 管理员 | 中方管理者，管理工厂、成员、术语表和 SOP 发布 | 是 |
| 审核员 | 双语员工，审核并修改 AI 译文 | 是 |
| 工人 | 越南语使用者，扫码查看 SOP 并提问 | 否（通过二维码访问） |

## 4. 核心流程

1. 管理员上传中文 SOP → 系统解析为步骤
2. 管理员提交翻译 → 系统按术语表调用大模型翻译
3. 审核员逐段审核 → 全部确认后，管理员发布为新版本
4. 管理员打印二维码，贴在工位
5. 工人扫码查看越南语 SOP，可以提问

## 5. 功能需求

|---|---|---|---|
| F1 | P0 | 作为管理员，我能创建工厂、邀请成员并分配角色 | 支持注册和登录；成员通过邀请链接加入工厂；访问其他工厂的资源一律返回 404，不暴露资源是否存在 |

| F3 | P0 | 作为管理员，我能管理 SOP 版本 | 状态流转：草稿 → 待审核 → 已发布 → 已归档；每次发布生成一个不可修改的版本号；可以查看历史版本；工人端只显示最新的已发布版本 |
| F4 | P0 | 作为管理员，我能维护中文 ↔ 越南语术语表 | 支持增删改查和备注；同一工厂内中文术语不能重复 |
| F5 | P0 | 作为审核员，我能审核 AI 译文 | 按步骤逐段展示原文和译文；标出术语未命中和低置信度的段落；逐段接受或修改；所有段落确认后才能发布；保留 AI 原始译文和人工修改记录 |
| F6 | P0 | 作为工人，我扫码后能在手机上看越南语 SOP | 无需注册登录；屏幕宽度 360px 时正常使用；可以切换查看中文原文；二维码链接不可猜测，管理员可以作废 |
| F7 | P0 | 作为工人，我能用越南语提问，得到基于 SOP 的回答 | 只基于本工厂已发布的 SOP 回答；回答附出处（SOP 名称和步骤号），点击可以跳转；资料中没有答案时明确说明，并建议联系主管；回答流式输出；按二维码和 IP 限流 |
| F8 | P0 | 作为工程团队，我能评估 AI 质量并监控调用 | 有离线评估集（翻译样本不少于 50 条，问答样本不少于 50 条）；一条命令运行评估并生成报告；每次大模型调用都记录模型、token 数、成本、延迟和结果；管理端能看到每日调用量和成本 |

| F10 | P1 | 作为管理员，我能批量导入术语 | 支持 CSV 导入，导入前可以预览，重复项有提示 |

## 6. 非功能需求

- **安全**：密码加盐哈希存储；全站 HTTPS；密钥不进代码仓库；上传文件校验类型和大小；定期对依赖做漏洞扫描
- **多租户隔离**：在数据访问层强制按工厂过滤，并有自动化测试覆盖
- **性能**（初始目标）：管理端普通接口 p95 < 300 ms（不含 AI 调用）；问答首个字返回 p95 < 3 s；一份 30 步的 SOP 翻译完成用时 < 2 分钟
- **可靠性**：大模型调用设置超时（30 s）和重试（指数退避，最多 2 次）；设置每日成本上限，超限后给出明确提示，而不是直接报错
- **可观测性**：结构化日志；每个请求有一个 request ID 贯穿全链路；错误集中上报
- **国际化**：管理端用中文，工人端用越南语；界面文案不写死在代码里；新增语言不需要改代码
- **部署与数据**：部署在新加坡区域；数据库每日备份，并完成至少一次恢复演练
- **隐私**：工人端不收集任何个人信息
